# 每日静默自更新

依据作者提供的只读方案：`E:/共享/tools/软件开发/skill 组件/skill 静默更新.md`。要求：每日首次使用比较本地与公开仓库版本；有新版静默更新；失败继续旧版，下次检测再试。没有修改该方案文件。

## 入口

仓库运行 `node scripts/self-update.cjs`；安装副本运行 `node <skill目录>/scripts/self-update.cjs`。默认无终端输出，失败不抛出到日更流程；诊断时可加`--verbose`，维护测试可加`--force`。正常使用不要每天force。

北京时间日期记录在仓库`.skill-update.json`；同日后续调用不再发起网络检查。每个git调用设12秒上限，禁止交互式凭据提示；失败不要求作者先修更新服务才能发文。并发检查使用排他锁，遗留超过10分钟的锁可清理。

更新源为该仓库已配置的上游分支，读取上游提交里的package.json正式三段版本号；仓库版本与SKILL metadata版本同步。只更新到更高版本，不降级，不仅因提交SHA变了就覆盖。发版时维护者必须递增版本，同时同步package-lock的根包版本。

## 实际保护与边界

- 上游只接受快进，工作树有未提交变更、分叉或安装副本被本地修改时保留旧版并记录原因。禁止为自更新丢弃作者修改。
- 先读取新版必需文件与依赖清单，再更新。此轻量更新通道只接受依赖不变的版本；依赖升级作为失败保留旧运行环境，不自动替换当前node_modules。维护者需另做安装迁移，不可宣称这类版本已更新成功。
- skill目录整包在同父目录临时目录组装，再重命名交换；失败还原旧副本。脚本、入口和引用一起更新，不只换SKILL.md。可写的本机仓库位置与安装版本记在`.runtime.json`。
- 仓库更新后若skill同步失败，使用`git reset --keep <检查前HEAD>`恢复本次快进，不递归删除仓库，不触碰被忽略的config、Cookie、稿件和发布账本。失败记录保留，下一天首次调用再试。
- 在当次业务启动前检查，发布过程中不热更。更新完成要重读skill；更新失败立即按仍在本地的版本执行今日任务。

## 安装与发布维护

`npm run skill:install`安装到`$CODEX_HOME/skills/fanqie-publisher-skill`，未设置时为用户`.codex/skills`。另一个目标路径可作为安装脚本参数传入；手工安装用于明确的首次部署或维护同步。

每次改流程/脚本后：更新版本、跑测试与skill校验、检查引用可用和无私人运行数据、提交远端。远端未推送的本地改动不是已经发布的更新；维护记录必须区分“本地完成”“本机已安装”“GitHub已同步”。
