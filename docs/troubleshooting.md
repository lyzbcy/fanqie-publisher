# 故障排查

## 无法连接 9333

确认独立 Edge 已用 `--remote-debugging-port=9333` 启动，并访问：

```powershell
Invoke-RestMethod 'http://127.0.0.1:9333/json/version'
```

## 登录失效

在独立 Edge 窗口使用番茄小说或番茄作家助手扫码。不要把验证码、密码或 Cookie 写入仓库。

## “下一步”不可用

章节号和标题使用 `fill()`；正文编辑器必须显式 `focus()`，清空后再次聚焦，再用 `keyboard.insertText()` 输入每个中文段落。不要用 `keyboard.type()`：新版 ProseMirror 可能只接受物理键事件并静默丢掉中文。脚本会在继续前回读三项内容。若正文字符不一致，保留截图并停止，不要改成 DOM 注入或强制点击。

## AI 声明无法验证

脚本只在“是否使用AI”的表单容器中选择“是”。页面改版导致定位失败时，应更新定位和验证逻辑；不要点击页面上其他同名“是”，也不要依赖默认值。

## 确认按钮被遮挡或 disabled

停止发布并检查页面错误信息。不得删除 `.arco-modal-mask`、改写 `pointer-events` 或使用 `force` 绕过页面校验。

## 重跑会不会重复发布

脚本同时检查后台章节列表和 `.publish-state/<book_id>.json`。任一侧出现同章号、同标题或账本记录，脚本都会停止。若要修订已发布章节，应在后台走编辑流程，不能把修订当作新章节重发。

## 如何防止第4章后误发第6章

发布第 N 章前有两层连续性门禁：本地账本必须完整包含 1—N-1；后台章节管理页的最新一行必须恰好是第 N-1 章，标题与 `manifest.json` 一致，状态为“已发布”。当前页只要出现断号、目标章已存在、前一章仍在审核，都会停止。提交后再次要求后台最新两行依次为 N、N-1；验证失败时不写账本，批处理不会进入下一章。草稿箱里的章节不算已经上线。

## 每两个段落之间出现很多空行

不要把包含空行的整篇正文一次性键入 ProseMirror。某些版本会把换行转换成多个空段。脚本会先按空行切成逻辑段，再逐段输入，并且只在相邻段落之间按一次 `Enter`。输入后会检查编辑器直属段落；除编辑器允许的末尾占位段外，只要正文内部出现空段就停止发布。

## 定时发布看起来设置了，但后台时间不对

必须同时验证三处：定时开关处于开启状态、日期与时间输入框的回读值完全匹配、提交后的章节管理页出现目标日期和时间。任一处不一致都不写入成功账本。使用 `--schedule=YYYY-MM-DDTHH:mm`，时间按北京时间解释。

## 提交后状态不确定

立即发布时必须确认对应章号、标题、连续序列及“已发布”，并通过后台预览全文核验后才写入账本。若尚未审核，只复查同章；若没有出现，查看系统临时目录中的 `fanqie-unverified-ch*.png`，核对后台，不要盲目重提。

## 提示“提交字数超出每日上限”

这是平台按当天累计提交字数执行的限制，不等同于固定章节数上限。脚本会在点击“确认发布”后即时捕获该提示，保存 `fanqie-rejected-ch*.png`，将当前章节留在草稿箱并停止后续批次。不要反复点击确认；下一可发布日从草稿章节继续。
