# 多作品日更：先覆盖、后加更

用于作者明确要求多部在更作品每天都更新的场景。授权创作与发布边界沿用主skill；暂停、完结或退出日更的作品须由作者确认，不能为凑额度自动移出启用书目。

## 先核两种额度

[官方第二版发文规则](https://fanqienovel.com/writer/zone/article/7639950766869839897)，2026-05-22起生效，2026-10-09核对原图：

|作者等级|账号每日可更新作品|单作品每日可提交字数|单作品每月可提交字数|
|---|---:|---:|---:|
|Lv.0/Lv.1|1本|<1万|<25万|
|Lv.2/Lv.3|3本|<2万|<50万|
|Lv.4以上|5本|<5万|<100万|

不能把单作品字数额度理解为账号共享总额度。每天先查询当前等级与平台余额；等级变化当日额度也变化，表格是核查依据而非永不更新的硬编码。更新作品数应包含账号其他已更新作品和当日定时占位，不能只数本地登记的两本。历史章节增补的字数也会占本书额度；不要通过改旧章、删章或切换入口绕过限制。

若剩余作品数不能容纳全部未更新书，减少每书字数也不能解决。必须明确“今天无法在当前额度下全部覆盖”，说明缺口并保留各书稿，先查合法升级/官方额度途径或取得作者明确的临时书目安排。不得继续默认交替断更、宣称两本已完成，或把第一本所有余稿发完才发现第二本被限。

## 基本目标与执行顺序

1. 实查所有启用书、待审、定时和草稿；只有当日实际已发布章节计入基本更新，不能用审核时间、今日补账时间、稿件存在或草稿数量代替发布时间。
2. 每书的基本目标来自作者约定及适用合同/推荐/福利规则。未有确定字数目标时默认一完整章。推荐验证的连续日更、全勤门槛与合同要求分别记录，不能把4000字当作所有协议的固定日更义务。参考[官方推荐规则](https://fanqienovel.com/writer/zone/article/7659317147297923134)。
3. 先把所有书下一章写好、审读和构稿；缺稿按已有自主授权补写。不能因一书没稿就默认把额度全投另一书，也不切割已发布内容凑更新。
4. 第一轮每书一章：A下一章确认已发布→B下一章确认已发布。若书目有已确认的基本字数要求，再按同样顺序逐轮补足。每章仍执行章号、前章已发布、全文/卷名与截图账本门禁。
5. 全部基本目标达成后，才按每书剩余额度和作者目标轮转加更。不借用其他书字数余额，不在未知余额下自动加更到上限。账户硬限制或登录失效立即停止对应提交，不能把拒绝当作审核中重试。

登记可按书配置`dailyMinimumChapters`（默认1）、`dailyMinimumCharacters`（默认0，确定有要求才填写）、`dailyTargetChapters`（可选加更目标），并设置`dailyPolicy.coverageFirst=true`。原本单书批量入口依然存在，但覆盖门禁会阻止第一本连发第二章时另一书仍未完成基本目标。脚本从实际时钟换算当前北京时间；`FANQIE_DAILY_DATE`与规划参数`--date`只用于与客户端日期交叉核对，不同日立即拒绝，先核实日期而非冒用另一日。

## 生成轮转计划

快照由Agent从实际后台生成，不要求作者手工填表。`source`为`fanqie-backend`，`day`为当前客户端北京时间日期，`verifiedAt`为真实核验时刻；超过10分钟需重新读取。`books`按书号记录可见行：`status`、`publishedAt`、`characters`；核对所有当日新章后标`completeToday=true`，若第一页全是当天章节则继续翻页，不能把截断列表当完整统计。`occupiesTodaySlot`包含定时等已占书数，`blockedByReview`标记需先复核的待审。`quota.remainingWorkSlots`为账号核实的剩余新作品槽位，`remainingCharactersByBook`按每书填日/月额度中较小的实际剩余值，不能填理论上限当余额。

```json
{
  "source": "fanqie-backend",
  "day": "YYYY-MM-DD",
  "verifiedAt": "真实UTC时间",
  "books": {
    "book-a": {"rows": [], "occupiesTodaySlot": false, "completeToday": true},
    "book-b": {"rows": [], "occupiesTodaySlot": false, "completeToday": true}
  },
  "quota": {
    "remainingWorkSlots": 2,
    "remainingCharactersByBook": {"book-a": 8000, "book-b": 8000}
  }
}
```

```powershell
node <仓库>/src/plan-daily.js --date=YYYY-MM-DD --registry='<登记路径>' --snapshot='<实时快照路径>'
```

该入口只规划、不发布；缺稿、短于每书`config.json`发布门槛、断号、哈希不符或额度不足会报错，不把一字稿算完整章。加`--extras`才考虑每书目标章数以内的加更，基本目标仍在前。按计划逐章调用单章发布器，不再先对A调用整批再对B调用整批。计划生成后后台若改变，重新读取并规划，不能盲用旧队列。

结束逐本记录“今日已发布章/字数、距基本目标的缺口、待发章、限制原因”，只有所有启用书均达标才能说“全部日更完成”。
