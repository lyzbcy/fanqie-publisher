# 自主创作与番茄日更

适用于“把今天的更新了”这种续作指令。沿用本作品已有授权：自主写作和发布都已获准时，完成全过程；只有发布权限时，只处理已有正文。尊重用户明确指定的每日数量、范围和时间。没有新增数量约定时，参考本书既有更新量与当前剧情合理安排，不把某次四章或7762字变成所有作品的硬限制。作者已要求发到限制或现有稿件发完时，执行该边界；不要为撞上限无尽写作。

## 定位与实查

1. 读取作品 README、最近交接、设定与正文，分清旧书、新书、完结季。配置的book_id必须与当前页面书名对应；有多本活跃书且无法从上下文定位时先澄清。
2. 实时读取后台章节管理和草稿箱，记录最新已发布章号、标题、字数、时间，查有无同章待审或草稿。没有源稿的新季不能冒充已完成；有自主续写授权的活跃书则续写下一批。
3. 后台优先于本地记忆。后台已有目标章：不重复提交；仅在后台预览全文与源稿一致、该章已发布且序列连续时补记账本。审核中只复查本章。账本有、后台无，或标题/全文不一致，停止并报告具体差异。

## 续写与校对

- 从最后一章真实正文接续；阅读设定和衔接记录，不从章目大纲冒认已写稿。沿用叙事口吻、人物目标、能力边界、年代及情感关系。每章推进一个可感知的行动或结果，章尾钩子来自尚未解决的冲突。
- 自检连续时间、地点、权限来源、资源来源、人物已知信息、证据强弱、承诺和未回收伏笔。检查人名及数字一致、专业判断是否把推断写成事实、角色是否凭空取得权限。按问题修改后再发布。
- 签约目标按平台实际字数与后台当日资格提示核对。超过作者目标阈值的那章应有已兑现的阶段胜利和明确后续钩子；规划的第几章或估算字数不能代替实际统计。签约机会数以后台为准，不承诺获签，不代签合同或编造实名资料。
- 正文只含正文，不放策划批注、模型指令、制作用语或字数统计。新稿落在该作品的正文目录，已发布章节未经修订授权不改写。

## 构稿与发布

合订源稿用 `## 第N章 标题`。保留此前全部章节的原正文，再调用 `<仓库>/src/prepare-novel.js <合订稿> <作品目录>/publish/fanqie/chapters`。每个已发布章节的标题与哈希必须仍与账本一致。执行待发范围的本地预检，然后用`publish-remaining.js --book-dir=... --from=N --to=M --publish --wait-for-review`。

父进程、每个子进程必须使用同一作品工作目录、配置和账本。环境变量BOOK_ID与该作品冲突应拒绝；不能让脚本切回发布器根目录从而使用旧书配置。范围起章、止章缺失必须报错，不悄悄缩小范围或跳到清单中的下一章。

每章执行：上一章连续已发布 → 正文填写并全文回读 → 无内部空段 → AI声明如实为是 → 提交 → 回读短暂拒绝提示 → 等审核 → 后台全文预览一致 → 写账本 → 才发布下一章。

审核中每20秒只复查本章，单章最多30分钟。每日字数限制、登录失效、选项变更、按钮不可用、错章或全文差异都停止，不把它们当审核中重试。等待超过期限保留未完成章的状态，向作者准确说明；不得称待审为已发布。

## 留存与交接

把临时截图复制进本书`publish/fanqie/evidence/`，文件名带北京时间日期及章号，避免其他书同章截图覆盖。记录更新前后的后台列表、今日各章标题/字数/发布时间/最终状态，新增与累计字数，并核验序列连续。

更新README的最新章与下一章、发布结果文件和正文衔接：已经发生的事实、剩余伏笔、下一次入口、待审或失败原因。工具会保存逐章哈希账本；交接文件不能取代下一次实时后台查询。

结束时关闭此次启动的专用浏览器；不要关闭用户平常浏览器或杀全部Edge。清理临时脚本，保留通用入口、正文和凭据。最终给作者实际发布范围、字数、状态与下一章即可。
